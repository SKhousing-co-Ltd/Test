# 管理者コンソール分離計画

## 目的

通常業務で使う画面と、システム保守・マスタ管理の画面を分ける。通常利用者の画面を見通しやすくし、管理機能へのアクセスを管理者に限定する。

この文書はリリース前に着手するための計画メモである。直ちに実装するものではなく、他の実装が進んだ後、リリース準備の段階で対象機能・権限・配備条件を再確認する。

## 合意した方針

- 通常業務アプリと管理者コンソールは、別URL・別配備とする。
- 同じGitリポジトリ内でアプリを分割する（モノレポ構成）。
- Supabase Authとデータベースは共用する。
- 管理者コンソールへのリンクは通常画面に残し、管理者に表示する。
- 管理者コンソールでの再ログインは許容する。
- 初期段階はアカウント・ロールによる制限を基本とする。VPNや接続元制限は要否を別途確認する。
- 画面の移行は一括ではなく、段階的に進める。
- 会社ドメインは未確認。初期はVercelのURLを利用し、利用可能なドメインが確認できた段階で専用URLを設定する。

## 機能の配置案

### 管理者コンソールへ移す候補

- アカウント管理
- 物件・アセット登録と設定
- テナント請求の共通設定
- スキーマ探索
- 案件移行検証

### 通常業務アプリに残す機能

- 案件一覧の確認
- AppSuite同期（日常的に使う可能性があるため）
- 契約・請求などの日常業務機能
- 駐車料金の整備、請求条件の一括設定など、業務管理者が業務上利用する機能

上記は現時点の合意に基づく候補であり、実装開始前に利用者・利用頻度と既存画面間の依存関係を確認する。

## 目標構成

```text
apps/
  operations/   # 通常業務アプリ
  admin/        # 管理者コンソール
packages/
  shared/       # 共通認証・権限判定・型・再利用UIなど
```

通常業務アプリと管理者コンソールはそれぞれ独立してビルド・配備する。Vercelの各プロジェクトを同じリポジトリの対象アプリに設定し、共通コードを共有する。具体的なワークスペース管理方式、Root Directory、ビルド設定は着手時に決める。

## 認証・認可

- 管理者コンソールでログイン状態と `user_profiles.role` を確認し、`admin` のみ利用できるようにする。
- 通常画面からのリンク表示制御に加え、管理者コンソールへの直接アクセスも保護する。
- フロントエンドの表示・ルート制御だけに頼らず、関連するテーブル、ビュー、RPC、Storage等のSupabase側ポリシーと権限を確認する。
- サービスロールキーなどの特権資格情報をブラウザーへ含めない。
- ネットワーク制限・VPN・MFAの追加要否は、セキュリティ要件と運用負荷を確認して判断する。

## 段階移行案

1. **着手前調査**：対象画面、利用者、操作権限、画面間リンク、DBアクセス、既存RLS、配備設定を確認する。
2. **アプリ基盤**：同一リポジトリ内に通常アプリと管理者コンソールのエントリ・ビルドを用意し、別URLへ配備する。管理者向けリンクと直接アクセス時の保護を整える。
3. **基本管理機能**：アカウント管理、物件・アセット登録・設定、テナント請求共通設定を移す。
4. **保守・検証機能**：スキーマ探索、案件移行検証を移す。案件一覧は通常業務アプリに残す。
5. **旧入口整理**：旧画面へのリンク、ブックマーク、直接URLへの扱いを決め、必要な場合は管理者コンソールへ案内する。
6. **リリース前確認**：両アプリの権限、通常業務の回帰、配備環境変数、Supabase AuthのURL設定、DBポリシーを確認してから公開する。

各段階の順序や対象範囲は、リリース前の再確認で確定する。移行中に通常業務アプリから管理機能へ案内する期間を設ける。

## 現状実装から見つかった確認点

- ルート定義は `src/App.tsx` にまとまっており、機能ごとの移設時にルートとナビゲーションを分離する必要がある。
- `/admin/schema-explorer`、`/admin/case-progress-migration`、`/settings/assets`、`/admin/assets`、`/settings/tenant-billing` には `AdminOnly` ガードがある。
- `/accounts` はナビゲーション上では管理者向けだが、ルート定義には管理者専用ガードがない。移設時に直接URLアクセスも含めた認可を確認する。
- AppSuite同期は通常アプリ側に残す案だが、現状は通常画面内にショートカットがある。表示対象とページ内の操作権限は別途確認する。
- 画面の分離だけではデータ権限は分離されない。関連するSupabaseポリシーを確認し、必要な場合は変更・検証する。

## 実装着手時の確認事項

- 管理者が使う会社ドメイン、管理用サブドメインの利用可否
- 管理者アカウントの範囲、退職・異動時の権限運用
- VPN・接続元制限やMFAが必要か
- 各候補画面の利用頻度と移行対象の最終確定
- 既存URL・リンク・ブックマークをどう案内するか
- 各機能が利用するDBテーブル、ビュー、RPC、Storage、Edge FunctionsとRLS
- Vercelのプロジェクト数・プラン・ビルド対象設定
- 移行期間とリリース前の回帰確認範囲
