# 基幹システム改善 やさしい説明版（正式版 1.1）

作成日: 2026-08-07
対象: 物件・契約を扱う担当者、承認者、マスタ管理者

## この仕組みでできること

物件の情報、レントロール、図面、契約書をつなげて管理します。普段の操作は、専門知識がなくても次の流れで進められるようにします。

```mermaid
flowchart LR
  A["物件の情報を整える"] --> B["Excelと照らし合わせる"]
  B --> C["図面を確認・登録する"]
  C --> D["契約書を確認する"]
  D --> E["正式版を出力する"]
```

## 毎日の仕事で行うこと

### 1. 物件情報をそろえる

物件ごとに、住所・地番・構造などを入力します。入力が足りない物件は「入力が必要」と表示されるため、一覧から順番に対応できます。契約書にどう表示されるかも、保存前に確認できます。

### 2. レントロールExcelを確認する

Excelをアップロードして、システムのデータと比べます。この操作だけでシステムの数字が勝手に変わることはありません。

違いがある場合は、画面で次のどれかを選びます。

- システムの内容を直す
- Excelの内容を直す
- 今回は除外する（理由を残す）

承認者がまとめて確認してから反映するため、誤って契約を消したり、数字を書き換えたりしません。

### DeskNet'sからの契約は、まず「対応依頼」になる

DeskNet'sで新規契約や契約変更が承認されても、レントロールの内容はすぐには変わりません。まずダッシュボードに対応依頼が作られます。

```mermaid
flowchart LR
  A["DeskNet'sで承認"] --> B["対応依頼が届く"]
  B --> C["担当者が差分を確認"]
  C --> D["Resolveして反映"]
```

対応依頼では、今の内容と反映予定の内容を並べて確認できます。区画や図面に問題がなければ「Resolveして反映」を選びます。内容を直す必要があるときは修正してから反映し、判断できないときは保留や差戻しにできます。

この仕組みにより、承認された契約を素早く確認しながら、誤った内容がレントロールへ入ることを防ぎます。

### 今回取り込んだデータを整える

今回のExcel取込で「確認が必要」になった契約も、同じ対応依頼の一覧で処理します。開発メンバーは、一覧から対象を開いて次の操作を行えます。

- Excelの元データと、現在のシステムの内容を見比べる
- 区画、商品区分、テナント、金額、期間を修正する
- 適用前に、変わる内容を確認する
- `Resolveして反映` を選んで反映する
- 判断できないものは保留にし、メモを残す

Excel取込の元データは書き換えません。修正した内容と、誰がいつ適用したかを残すため、あとから確認できます。

## システムを作るときの分担

システムの土台は、最初にしっかり作ります。普段のデータ調整は画面から行います。

| どこで作るか | 何をするか |
| --- | --- |
| システムの土台 | 契約や区画のつながり、確認状態、履歴、間違った内容を防ぐ仕組みを作る |
| 操作画面 | 一覧を見る、差分を確認する、内容を修正する、Resolveして反映する |

現在は開発メンバー全員が修正・適用できます。将来、運用担当者が使い始めるときは「担当者は修正まで、承認者が反映」の形へ切り替えられます。

### 3. 商品ごとに見る

レントロールでは、次の商品をチェックで表示／非表示にできます。

- 事務所
- 駐車場
- 駐輪場
- 看板
- 倉庫
- アンテナ

表示している商品の合計と、全体の合計を並べて表示します。Excelで出力する場合も、画面と同じ条件になります。

### 4. 図面を登録する

物件を選ぶと、階ごとに状態が分かります。

| 表示 | 意味 | 次にすること |
| --- | --- | --- |
| 完了 | 図面と区画の配置がそろっている | そのまま利用できます |
| 図面未登録 | その階の平面図がまだない | 「図面を登録」を選びます |
| 未配置区画あり | 図面はあるが、置かれていない区画がある | 区画を選んで図面上に置きます |
| 確認が必要 | 階や区画の情報に食い違いがある | マスタ管理者に確認を依頼します |

図面がない階は灰色で表示され、誤って編集することはできません。図面を登録すると自動的に使える状態になります。

### 5. 契約書を作る

契約書は次の順番で進めます。

1. 下書きを保存する
2. 契約の内容と、添付する図面を画面で確認する
3. 承認を依頼する
4. 承認後に正式版を出力する

図面に置かれていない区画がある場合は、契約書を出力できません。先に図面を完成させる必要があるため、添付漏れを防げます。

一度出力した正式な契約書は、その時点の図面と一緒に保存されます。あとから図面を直しても、過去に出した契約書は変わりません。

## 電気代単価について

契約している区画ごとに、電気代の単価を登録します。単価には開始日を付けるので、契約途中で金額が変わっても履歴を残せます。

将来は、検針値を取り込むと「使った電気の量 × その時期の単価」で請求額を計算できるようにします。今回の段階では、まず単価を正しく登録・表示できるようにします。

## 困ったとき

「作業待ち一覧」に、対応が必要なものをまとめて表示します。

- 入力が足りない物件
- Excelと違う数字
- 図面に置かれていない区画
- 出力に失敗した契約書

誰が対応するか、いつ確認したかも残るため、口頭やメールだけで管理する必要がありません。

## 役割の分け方

| 役割 | 主な仕事 |
| --- | --- |
| 担当者 | 確認、入力、図面登録、契約書の下書き |
| 承認者 | 大きな変更や正式出力の確認・確定 |
| マスタ管理者 | 物件・階・商品の情報を整える |

担当者が誤って大きな変更を確定できないようにしつつ、普段の作業は止めずに進められるようにします。

## 大切な約束

- Excelを照合するだけでは、システムの内容は変わりません。
- 大きな変更は、確認してから確定します。
- 過去に出した契約書や図面は、あとから変わりません。
- 何か足りないときは、理由と次にすることを画面に表示します。
