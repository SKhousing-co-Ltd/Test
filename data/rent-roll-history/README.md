# 過去レントロール取込作業領域

## 目的

過去のレントロールを、まずは契約履歴として確定登録せず、基準日時点のスナップショットとして利用できる形に整える。

対象とする確認内容は次のとおり。

- 基準日時点の賃料・共益費・その他月額収入
- 区画ごとの入居状況
- テナント名・テナントコード
- 物件・棟・階・区画の対応
- 空室数、賃料合計、収入合計などの収支確認

## 取込方針

過去の契約情報を現在の契約マスタへ上書きしない。各ファイルの基準日を持つスナップショットとして扱い、現在の契約状態と分離する。

基準日はファイル名に含まれる日付を採用する。例えば、`2020.10.1` は `2020-10-01` として扱う。

空室も区画レコードとして保持する。解約予定は入居中として集計し、解約予定であることを別フラグ・注記として保持する。

収入は、賃料・共益費・駐車料・その他収入を別項目で保持する。その他収入は賃料等へ合算せず、独立した項目として集計できるようにする。

面積は㎡と坪を別項目で保持する。元帳票に両方の値がある場合は元の値を優先し、片方だけの場合のみ `1坪 = 3.305785㎡` で補助換算する。

同一基準日のファイルが複数ある場合は、ファイルの更新日時が新しいものを採用する。採用しない候補ファイルも削除せず、採用・不採用の判定結果をレポートに残す。

アセットマスタに存在しない物件は取込対象から除外する。物件名が未特定、またはアセットマスタへ対応付けできない場合も同様に除外し、対象ファイル・シート・理由をレポートに残す。

空室の賃料は元帳票に記載があれば参考値として保持するが、収入合計には含めない。

敷金・礼金・更新料・保証金は月額収入に含めない。元帳票に記載がある場合は、月額収入とは分離した一時金・預り金項目として保持する。

通常レイアウトで読み取れない特殊レイアウトは初回取込から除外する。除外したファイル・シート・理由はレポートに残し、後続対応の対象とする。

正式な契約履歴として登録するかどうかは、スナップショットの検証後に別途判断する。
